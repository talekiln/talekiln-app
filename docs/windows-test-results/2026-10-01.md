**失败原因（环境问题，非代码）**：百炼已生成图片，失败发生在下载结果图：`https://dashscope-a717.oss-accelerate.aliyuncs.com/...png` 在本机 Node 里 `fetch failed EAI_AGAIN`，下载器重试 6 次后放弃。本机 DNS 服务器是路由器 192.168.1.1，解析 `*.oss-accelerate.aliyuncs.com` 返回 SERVFAIL（`nslookup`、Node `dns.lookup` 一致）；用 223.5.5.5 / 114.114.114.114 能解析（47.254.187.130 / 8.208.41.115）。`dashscope.aliyuncs.com` 本身可解析，所以文本模型和提交任务都正常。需要把本机 DNS 改成公共 DNS 后重跑，本次未改系统设置。

**花费**：脚本按价格表估算为 0 元（该估算不含任务用量回写，见脚本说明）。实际每次运行产生了：文本模型调用 1 次、文生图 1 次、文生视频任务提交 1 次（视频任务提交后无人取结果，可能仍被计费）。共 2 次运行，真实金额请以百炼账单为准，预计远低于单次 5 元上限。

### 给云端的观察（不改）

1. 脚本在角色图阶段失败前就已提交了文生视频任务（`video_t2v_submit`），失败中止时没有取消，会产生无结果的花费；建议先确认图片阶段再提交视频，或中止时取消任务。
2. 结果图下载失败时错误只显示 `NETWORK 网络请求失败`，看不出 DNS 原因和 URL 主机；建议在错误信息里带上 `cause.code` 和主机名。

**timeline 失败（业务逻辑，不改，交云端）**：e2e 脚本提交的时间线每个分镜带多于一条字幕，被时间线图的校验以 409 拒绝。要么脚本拆字幕的方式不符合“字幕由台词行推导”的新规则，要么校验过严。与 Windows 无关。因此导出阶段在本机仍未经 e2e 验证。

**结论更新**：前 9 个阶段通过，timeline 和 export 未通过；真 Key 测试整体仍未通过，需云端修 timeline 阶段后再跑。
