# Windows 真机测试结果 2026-10-02

环境同 2026-10-01：Windows 11 Home 中文版 10.0.26200；Node 25.9.0；pnpm 10.28.0；Rust 1.99.0（MSVC）。分支 `win/testing`。

## 任务 3：配音进队列、真实花费回写、画布新增节点（2026-10-02）

### 做了什么

- **配音进队列**：`POST /episodes/:id/voiceover` 的估价 / 确认 / 402 上限语义不变；`confirm:true` 改为逐镜建 `/ai-tasks`（`kind: tts`，参数带 `_vo` 回写信息），返回 `{tasks, skipped}`，任务中心里显示为“镜头 #N · 旁白配音”。worker 完成后 `packages/local/src/voiceover/queue.js` 读音频 / 词时间戳 blob，在一个事务里经内核 `recordGeneration` 写旁白版本（含词级字幕块），再物化旧列；合成期间台词或音色改过则 `STALE_INPUT` 跳过；启动时 `recoverFinished` 补写崩溃前已完成的任务（幂等）。新增 `GET /episodes/:id/voiceover/status`（逐镜 none / queued / running / failed / stale / fresh），时间线编辑器的“旁白配音”抽屉提交后每 2 秒轮询并显示“配音中：N 个排队，M 个生成中”，完成后刷新。
- **真实花费回写**：provider 结果带 `usage`（视频 `duration` + `SR`、配音 `characters`、图片张数）；`spend.actual()` 按价目换算后写 `spend_log.actual` 与 `spend_log.usage`（迁移 `28_spend_log_usage.sql`）；`summary.total` 多 `estimated / actual / actual_count`，`prices` 带 `version / date / sample`。花费页：顶部说明“费用按百炼公开价目计算（2025-12-19 版）”，合计卡显示预估合计与“实际 ¥x（已回传 a/b 个任务）”，逐任务表加“实际”“用量”列（如“5 秒 × ¥1.00（1080P）”“120 字符 × ¥0.0002”）。
- **价格表**：`packages/local/configs/prices.json` 换为百炼公开价目（2025-12-19，来源见文件 `source`）：wan2.6-t2v 0.6 元/秒（720P）/ 1.0 元/秒（1080P）、cosyvoice-v2 2 元/万字符（汉字计 2 字符）、wan2.6-t2i 0.2 元/张，这三条已核对（`verified:true`）。
- **画布**：工具栏“新增节点”（shot / script_line / image / video / narration；镜头与剧本行需选场景组，经 `canvas.addNodeAt`，新节点放在最右侧并自动选中）；未选中节点时属性面板列出场景组，可改名（新意图 `canvas.renameGroup`，去空白、非空、≤200 字）。时间线页的两个本地撤销 / 重做按钮移除，Ctrl+Z / Ctrl+Shift+Z 改为先保存未提交编辑再走内核历史（与顶栏撤销同一份）。

### 未完成 / 待产品决定

1. **价目未逐条核对的模型**（`wan2.6-image`、`z-image-turbo`、`wan2.6-i2v-flash`、`wan2.6-r2v-flash`、`wan2.2-kf2v-flash`、ark 全部）：公开价目页没有单列，保留占位价并标 `verified:false`，估价时界面按“示例价”提示。要不要把这些模型从下拉里收起、或找到对应价目后补上，请产品决定。
2. **时间线轨道的音量 / 静音 / 混音**在图外（`PUT /timelines` 直写），内核撤销不恢复它们；时间线 store 里旧的本地历史代码保留但不再绑按钮。
3. **画布属性面板**里 image / video / narration / compose 的参数仍用裸 `setParam` 事务（每次点击一步撤销），没改为意图。
4. **真 Key 在界面里跑配音 + 看实际花费回传**：本机未设置 Key 环境变量，未执行。
5. `exportE2E`（真 lycore 导出）在整个 local 套件并行跑时出现过一次 `timeout: encoder.detect`，单独重跑通过，属环境抖动；若 CI 再现需把 encoder 探测的超时放宽。
6. 云端目录（`GET /catalog`）里的价格仍是旧的示例价，需要云端同步更新为公开价目，否则本地拉到目录后会覆盖内置价目。

## 任务 4：Windows 人工检查（2026-10-02）

### 怎么测

- 用当前代码重新打包 unpacked（`node scripts/pack-desktop.mjs --win --dir`，Electron 39.8.10），直接运行 `apps/desktop/release/win-unpacked/Talekiln.exe`：`--remote-debugging-port` 驱动页面逐个打开并收集控制台异常，`--inspect` 进主进程只做四件事：调 `BrowserWindow.close()` / `show()`、调 `app.quit()`、手动 `powerMonitor.emit('resume')`、在 `Notification.prototype.show` 上打一个只记日志的探针。
- 用户数据目录：`%APPDATA%\talekiln` 先改名备份，再用目录联接指到 `…\tmp\中文 目录\talekiln`（Electron 不认 `APPDATA` 环境变量覆盖，只能这样做），所以数据库、密文文件、默认导出目录全在中文 + 空格路径下；ffmpeg 通过 `LYCORE_FFMPEG_DIR` 指到 `…\中文 目录\ffmpeg 工具`。测完已把原目录恢复。
- Key 用假值 `sk-dummy-safestorage-TEST1234`（不是真 Key），只用来验证加密落盘、重启后可用和日志脱敏；本机没有设置真 Key 环境变量。

### 发现的问题 / 观察（不改，交云端判断）

1. 时间线页在剧集还没组装时间线时，`GET /timelines/episode/1` 返回 404，页面把同一条提示“该剧集尚无时间线。建议：刷新页面；数据可能已被删除”弹了两次（两处在报同一个错），而且这条建议对“还没组装”这个正常状态不合适，应改成引导去组装 / 从分镜生成。
2. 开发模式（electron 直接跑仓库）在本机起不来：根目录 `better-sqlite3` 是按 Node 25（NODE_MODULE_VERSION 141）编译的，Electron 39 要 140，启动即弹“本地服务未能启动”。打包路径（`scripts/pack-desktop.mjs` 先 deploy 到 `.stage`）正常，所以只影响开发态；要么给 desktop 包加 electron-rebuild 步骤，要么在文档里写明只用打包路径测。
3. 场景缓存二次导出是 4/5 命中而不是 5/5（同参数、没改任何镜头），有一个场景每次都重渲，可能是某个场景的缓存键里混了时间戳之类的东西，值得查一下。
4. `app.getPath('userData')` 固定为 `%APPDATA%\talekiln`，改 `APPDATA` 环境变量也不认；测中文 / 空格数据目录只能靠目录联接。以后若要支持自定义数据目录，需要启动参数或配置项。
5. 本机 ffmpeg 构建没有 `libx264`（`available:false`）；若用户机器没有任何硬件编码器且 ffmpeg 同样构建，回退只剩 `h264_mf`（Media Foundation）。打包带的 ffmpeg 是否含 libx264 要在 CI 产物上再确认。
