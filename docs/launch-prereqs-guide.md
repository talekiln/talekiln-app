## 1. 测试账号和邀请码（现在就能做）

云端已有邀请码机制（管理后台 `apps/admin`，接口 `POST /admin/invites`、`GET /admin/invites`、`POST /admin/invites/:id/revoke`）。

1. 部署云端：按 `docs/cloud-deploy.md` 准备 Postgres 和环境变量（`DATABASE_URL`、`JWT_ACCESS_SECRET`、`LICENCE_PRIVATE_KEY_PEM`、`ADMIN_EMAIL`、`ADMIN_PASSWORD`）。这些都只放服务器环境变量或托管平台的密钥管理，不进 git。首次启动会自动建管理员，之后把 `ADMIN_PASSWORD` 从环境里删掉。
2. 登录管理后台，批量生成邀请码（建议 25 个：20 个发测试者，5 个备用），设有效期（如 14 天），每个测试者一个码。记录“码 -> 发给谁”，用表格自己留，不要放仓库。
3. 发给测试者的内容：安装包链接、邀请码、注册方式、他们需要自备的百炼 Key 申请指引（Key 只放自己电脑），和反馈入口（应用内“导出诊断包”）。
4. 测试期间在后台看激活数、反馈和遥测；测试结束统一吊销未用的码。
5. 云端放哪里是个决定：放国内云（访问快，但要 ICP，见第 4 节）还是先放海外或临时用国内云的测试环境。内测 20 人可以先用一台小机器，域名先不对公众开放。

我能代劳的：写一份发给测试者的说明和问卷，生成邀请码发放表模板。我不能代劳：买服务器、注册域名、实际登录后台生成码（需要你的凭据）。

## 2. 代码签名证书

目标：让 Windows 安装包带有效签名，减少 SmartScreen 和杀软拦截。技术侧已就绪（`docs/release-signing.md`，CI 有签名骨架，没证书时自动出未签名包）。

1. 先确定签名主体：个人还是公司。多数证书机构对代码签名要求组织验证，没有公司主体，选择会很少，要问机构是否接受个体工商户或个人。主体名要和 `apps/desktop` 的 `publisherName` 一致，自动更新会校验它，以后换主体旧客户端会校验失败，所以先定主体再买。
2. 选方案（见 `docs/release-signing.md` 第 1 节表格）：近年行业规则要求私钥放在硬件或云 HSM，所以多数新证书不再给可下载的 `.pfx`。我们用 GitHub 托管 runner 构建，最省事的是云签名服务（如 Azure Trusted Signing、DigiCert KeyLocker、SSL.com eSigner，是否对你所在地区和主体开放要看各家当前政策）。如果买了 USB 令牌，就得用自己的 Windows 机器做签名机。
3. 内测期怎么办：20 人内测可以发未签名包，告诉测试者“更多信息 -> 仍要运行”，并提前和他们说杀软可能提示。公开发布前再上证书。EV 不保证立即消除 SmartScreen 警告，信誉要积累。
4. 拿到证书后：把凭据放进 GitHub Secrets（名字见 `docs/release-signing.md` 第 2 节），在 CI 里实际跑一次签名构建，用 `Get-AuthenticodeSignature` 确认状态是 `Valid` 且带时间戳，再把包过 VirusTotal 和国内常见杀软。这一步的 CI 骨架还没在真实凭据下跑过，到时可能要调。
5. 凭据不要发给我，也不要贴到聊天里；由你自己在 GitHub Secrets 页面填入。

## 3. 法务意见

找一位懂互联网和 AI 合规的律师（或所在地律所的 TMT 团队），一次性问清下面这些问题，让对方出书面意见：

- AI 生成内容：本产品调用第三方模型生成图像、视频、语音。用户自备 Key，我们不托管模型。深度合成和生成式 AI 的管理规定下，我们是“服务提供者”还是“技术支持者”？是否需要算法备案或其他备案？应用已实现生成内容显式标识和元数据标识（见 `docs/aigc-marking.md`），这样是否够用？
- 用户内容与肖像、声音：用户输入的角色参考图和文本，涉及真人肖像或声音时，我们需要什么提示、协议和禁止条款？
- 隐私与数据：本地为主，云端只存账号、授权、遥测和反馈（诊断包已脱敏）。需要的隐私政策、用户协议、个人信息处理告知、跨境传输（如果云端或遥测在境外）怎么写？
- 推广返佣：在“添加 Key 向导”里放阿里云等平台的推广链接，需要什么披露方式？和平台的合作条款有哪些限制？
- 开源：开源部分计划用 AGPL-3.0 加 CLA，插件 SDK 用 MIT；闭源核心 `lycore` 与上游 LocalMiniDrama（MIT）分叉代码的许可证合规（`docs/licenses.md` 已列清单，ffmpeg 用 LGPL 方式见 `docs/ffmpeg-lgpl.md`）。
- 收费前：软件订阅的合同、发票、退款条款，以及第三方模型输出的版权和责任划分。
- 品牌：故事窑 / Talekiln 的商标检索和注册（软件 9 类、网络服务 42 类，可能还有 41 类），域名 talekiln.ai 是否已注册。

## 4. ICP 备案

先判断要不要：

- 桌面应用本身不需要备案。需要备案的是“在中国大陆境内的服务器上对外提供服务的网站/域名”。我们的云端（账号、授权、更新、管理后台）如果部署在大陆机房并绑定域名，就需要。
- 如果云端放在境外机房，一般不走大陆 ICP 流程，但大陆访问速度和稳定性可能差，且依赖境外服务也要在法务问题里问清楚。
- 如果以后在国内应用商店上架或做面向公众的官网，要另外看对应的备案和资质要求。

办理路径（以大陆云厂商为例）：

1. 有主体：企业营业执照（个人也能备案网站，但用途和命名限制更多，且商业用途建议用企业）。
2. 有域名（域名实名认证完成）和大陆云服务器（备案由云厂商代为提交，需要在该厂商买至少一台符合要求的服务器或服务）。
3. 在云厂商备案系统填资料、上传证件、做人脸核验或幕布照片，厂商初审后提交管局，通常需要等待管局审核；备案期间域名不能正式解析到大陆服务器对外访问。
4. 通过后在网站底部放备案号，并做公安联网备案（有此要求的地区）。

时间不确定，不同省份差别大，按“几周”预留，不要排进上线日期。我建议：内测用不备案的方式（境外小机器或内网/IP+测试域名只对测试者开放），同时并行启动企业主体和域名的准备。
