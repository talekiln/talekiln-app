# 二期开发计划（云端会话视角，2026-10-01 起草）

依据：三期总方案“二期”一节（公开下载、专业版收费、推广返佣上线、外壳开源）。一期里已经提前做掉的部分：项目图内核与四视图最简版、AIGC 标识、自动更新骨架、云端管理后台雏形、推广跳转。下面只列还没做的。

## 分工原则

- 云端会话：Linux 上能做、能测的一切；需要外部账号的部分先写成接口加模拟实现，账号到位后只换配置。
- 本地会话：Windows/macOS 真机验证；一期收尾四项（见 `docs/local-session-tasks.md`）。
- 为避免冲突，二期早期不碰本地会话正在改的文件：`apps/desktop` 主进程、出图/出视频按钮与队列接线、配音、花费回写、画布节点增删。

## 工作包

| 包 | 内容 | 能在云端独立做 | 卡在什么 |
|---|---|---|---|
| P2-B 收费与授权 | 套餐与版本、订单、支付、退款（按剩余天数折算）、发票登记、设备数限制、授权令牌带权益（免费/专业）；微信 Native、支付宝扫码做成支付适配器接口，先带沙箱模拟实现 | 是 | 真实商户号、回调域名与 HTTPS；微信/支付宝证书 |
| P2-C 登录 | 短信验证码登录、微信扫码登录的服务端与适配器接口，带模拟实现；桌面登录页加入口 | 服务端是 | 短信签名与模板审批、微信开放平台应用 |
| P2-E 导出 | 从内核时间线投影导出剪映草稿、Premiere/FCPXML、抖音/视频号尺寸预设；输入输出做成纯函数，单测对照样例 | 是 | 剪映草稿格式随版本变化，需要真机用最新版剪映打开验证 |
| P2-D 体验 | Ctrl+K 命令面板、PR 键位预设与自定义键位、版本历史界面（内核已有版本和撤销日志）、画布完整版 | 命令面板、键位、版本历史是；画布等本地做完节点增删后接 | 与本地会话的界面文件冲突，晚一批开 |
| P2-A 项目文件夹 | 一个项目一个文件夹（project.json + project.db + media/）、`.lyproj` 导入导出、一期单库自动迁移 | 是，但改存储层，风险最大 | 等本地的队列和写回改动合并后再开，否则冲突 |
| P2-G 开源准备 | 仓库拆分方案（开源外壳 / 闭源 lycore）、AGPL-3.0 与 CLA 机器人配置、贡献指南、插件 SDK（MIT，厂商适配器插件）、双仓库 CI | 是（文档、SDK、CI） | 法务确认许可证与 CLA 条款；公开仓库的名字和时机由你定 |
| P2-H 后台与官网 | 后台扩到约 14 屏（订单、退款、套餐、版本灰度、公告、管理员、审计）、推广漏斗、官网与下载页 | 后台是；官网静态页是 | 域名、备案、托管 |
| P2-F macOS | CI 增加 macOS 构建（未签名）、路径与进程差异审查、签名公证脚本骨架 | CI 与审查是 | 一台 Mac 真机验证；Apple 开发者账号做签名公证 |
| P2-I 合规文本 | 隐私政策、用户协议、举报入口页面的初稿 | 初稿是 | 必须经律师审阅，不能直接用 |
| P2-J IPC | 界面与本地服务从本机 HTTP 改为 Electron MessagePort | 可以，但动 desktop 主进程 | 放到二期后半，等本地会话的桌面主进程改动稳定 |

## 建议批次

1. 第一批（互不冲突，可并行）：P2-B、P2-E、P2-G、P2-D 中的命令面板与键位。P2-C 的服务端和 P2-H 的后台扩展同改云端，排在 P2-B 之后或同批但合并时人工整合。
2. 第二批：P2-D 版本历史与画布完整版、P2-C、P2-H、P2-F CI。
3. 第三批：P2-A 项目文件夹迁移（等一期收尾合并）、P2-J。
4. 持续：P2-I 文本、回归测试、文档。

## 需要你决定或办理的

- 支付商户、短信签名、微信开放平台应用：账号办好后只需填配置。
- 开源：仓库名、公开时间、AGPL 与 CLA 是否经法务确认。
- 代码签名、Apple 开发者账号（见 `docs/launch-prereqs-guide.md`）。
- 定价是否沿用 39 元/月、299 元/年（只影响配置）。

## 验收口径（二期）

自动化：内核一致性套件保持 0 失败；云端支付与授权用沙箱和并发测试覆盖（重复回调幂等、退款折算、设备数上限）；导出器对样例项目的输出做结构断言。人工：Windows 和 macOS 真机、剪映真机打开草稿、真实支付走通一单（商户号到位后）。
