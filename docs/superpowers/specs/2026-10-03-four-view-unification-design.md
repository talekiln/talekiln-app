# 四视图统一工作台：放弃 LocalMiniDrama 旧交互的改造方案

状态：待评审（设计稿，未实施）
日期：2026-10-03
UI 线框：https://claude.ai/artifact/AMhnpTL2cGa5GgJHvxTaqG （私有链接，需要所有者在页面的 Share 菜单里分享后别人才能打开）

## 1. 目标与边界

### 1.1 用户的要求（归纳）

1. 放弃 LocalMiniDrama 原来的交互：`FilmCreate`（八步左侧导航）、`DramaDetail`（剧集管理页）、`DramaCanvas`（旧画布）。
2. 以我们自己的四视图（剧本 / 分镜 / 时间线 / 画布）作为唯一的项目工作区。
3. 旧页面的功能**增量地**并入四视图，而不是一次性重写。
4. 四视图要有一致的通用元素，例如“导出”在每个页面都能用。
5. 给出 UI 设计，并按“由 Claude 来改”评估工作量。

### 1.2 本方案的假设（需要确认）

- A1 **首页保留**：`FilmList` 继续做项目列表，但卡片点进去直接进四视图，不再经过 `DramaDetail`。
- A2 **四个视图标签不变**：角色 / 场景 / 道具不做成第五个标签，而是左栏入口 + 资产面板 + 一个“资产库”整页（理由见 §4.3）。
- A3 **这一轮不给内核加角色 / 场景 / 道具节点**。资产继续用旧表（`characters` / `scenes` / `props` 及各库表），镜头与资产的绑定继续走已改道内核的 `PUT /storyboards/:id`（见 kernel-design §12.1）。这不违反“分镜 / 时间线表只能经内核写”的规则。
- A4 只支持现有的两个服务商适配器（百炼、方舟）。只对 Kling、Grok 等未接入服务商有意义的功能直接删除；Seedance 2.0（方舟）相关功能按能力开关显示。
- A5 旧路由保留一个版本的重定向，旧书签和外部链接不失效。

### 1.3 不做的事

- 不改内核数据模型，不新增内核意图（D3 的“事务化重新生成分镜”只组合现有的增删镜头操作）。
- 不实现上层目录前端规格（`docs/ai-video-editor-frontend-spec.md`，不在本仓库）里的“全片提示词栏”等新交互；本轮只做迁移与统一。
- 不做云端 / 协作相关改动。

## 2. 现状

| 页面 | 行数 | 去向 |
|---|---|---|
| `views/FilmCreate.vue` | 10,843 | 删除；功能拆进四视图 |
| `views/DramaDetail.vue` | 1,529 | 删除；分集进左栏，项目信息进“项目设置” |
| `views/DramaCanvas.vue` + `components/dramaCanvas/*` + `useCanvas*.js` + 三个 utils | 5,473 | 删除；内核画布 `CanvasView` 取代 |
| `views/FreeCreate.vue` | 586 | 删除（入口早已隐藏） |
| `composables/filmCreate/*` + `useStoryGeneration.js` | 2,446 | 搬迁复用，不删除 |
| 四视图相关页面（Script / Storyboard / Timeline / Canvas / Workbench / ReferenceLibrary / Export / Batch / NewProject） | 约 3,000 | 扩充 |

旧页面里指向旧路由的跳转共 13 处。四视图自己也有 3 处仍指向旧页面：`ViewSwitcher` 的“项目”返回键、`TimelineEditor` 的返回键、`BatchPage` 的返回。

盘点中顺带发现、本方案会一并修掉的问题：

1. `useCharacters.js` 调用不存在的 `dramaAPI.getCharacters`，“本剧所有角色”永远为空。
2. `GET /dramas/:id/scenes`、`add-to-team-library` 前端在调，后端没注册；`POST /episodes/:id/characters/extract` 是空实现。
3. `POST /episodes/:id/storyboards`（AI 生成 / 重新生成分镜）会 `resetGraph`，清掉该集的撤销历史与版本关联。
4. `ReferenceLibrary` 出候选图、`ShotWorkbench` 的“旧流程生成”仍走直接扣费的旧 `POST /images` / `POST /videos`，在 `generation.legacy_enabled` 关闭时（默认）会返回 402。
5. 旧画布的节点位置存在 `dramas.canvas_layout`，与内核画布不共享。

## 3. 三种做法

**做法一（推荐）：先搭统一外壳，再按视图分批迁入，最后删旧页面。**
第一期就让四视图共用一个外壳（顶栏、左栏、检查器、状态栏），旧页面代码暂时保留但不再有入口。之后每个 PR 迁一组功能并带测试，全部迁完再删旧代码。好处是每一步都可发布、可回退，评审粒度小，最符合“增量融合”。代价是迁移期间新旧代码并存两到三周。

**做法二：保留“旧流程”入口，边用边迁。**
与做法一相同，但首页和外壳里保留一个“旧流程”按钮。两套交互长期并存，用户要记两套操作，迁移完成时间不确定。只有在迁移期间必须继续用旧流程出片时才值得。

**做法三：按上层目录前端规格（`docs/ai-video-editor-frontend-spec.md`，不在本仓库）的四区布局整体重写。**
一次性换成“预览居中 + 底部时间线”的单页编辑器。改动最大，四视图与内核视图投影都要重做，风险集中在一个大 PR 里。不推荐在本轮做。

## 4. 设计

### 4.1 统一外壳 `ProjectShell`

项目内的所有页面（四视图、镜头工作台、资产库、批量生成）都渲染在同一个外壳里，只换中间区域。

```
+------------------------------------------------------------------------------------------+
| 故事窑 | 雨夜来信 / 第1集 v | [剧本|分镜|时间线|画布] | 待生成3 任务2 花费 历史 撤销 重做 | 生成v | 导出v |
+--------------+-------------------------------------------------------+-------------------+
| 分集          |                                                       | 检查器             |
|  01 雨夜来信   |                当前视图的主体                           | 随选择变化：        |
|  02 旧书店的灯 |                                                       | 行 / 镜头 /        |
|  新建 批量导入 |                                                       | 片段 / 节点         |
| 资产          |                                                       |                   |
|  角色4 场景3 道具2|                                                    |                   |
| 项目          |                                                       |                   |
|  批量生成 项目设置|                                                    |                   |
+--------------+-------------------------------------------------------+-------------------+
| 已保存 . 本集12镜58秒 . 16:9 . 风格 . 模型 . 渲染核心状态 . Ctrl+K                            |
+------------------------------------------------------------------------------------------+
```

每个项目页都必须有的通用元素（这就是“一致风格”的清单）：

| 元素 | 内容 | 现有来源 |
|---|---|---|
| 项目 / 分集切换 | 顶栏下拉；切集保留当前视图 | 新增（取代 `resolveDrama` 扫项目列表） |
| 视图标签 | 剧本 / 分镜 / 时间线 / 画布；切换时保留选择 | `ViewSwitcher` |
| 待生成徽标 | 点击后在当前视图只看过期项 | `ViewSwitcher` |
| 任务 | 抽屉，不离开当前页；显示进行中数量 | `TaskCenter` 改成抽屉 |
| 花费 | 本项目累计；点击打开花费页 | `SpendPage` |
| 历史、撤销 / 重做 | 内核历史，四视图共用 | `ViewSwitcher` |
| **生成菜单** | 一键成片、只补齐过期、全部首帧 / 视频 / 配音、导演模式、多集批量 | 见 §4.4 |
| **导出菜单** | 成片、工程、素材与项目三组 | 见 §4.5 |
| 左栏 | 分集列表（新建、批量导入、改名、删除、排序）、资产入口、项目设置 | `DramaDetail` |
| 检查器 | 同一个选择在四个视图里显示同一个检查器组件 | 新增 `ShotInspector` 等 |
| 状态栏 | 保存状态、本集统计、画幅、风格、模型、渲染核心是否可用、命令面板提示 | 新增 |
| 快捷键 | Ctrl+Z / Ctrl+Shift+Z、Ctrl+K、Ctrl+E 打开导出菜单 | `useKeymap` |

外壳的公共对话框只有一份实现，任何视图都能唤起：生成确认（`GenerateDialog`）、导出、项目设置（标题、画幅、风格、语言、片段时长、大纲）。

路由统一为 `/p/:dramaId/e/:episodeId/:view`（view 取 script / storyboard / timeline / canvas）。镜头工作台为 `/p/:dramaId/e/:episodeId/shot/:shotId`，资产库为 `/p/:dramaId/assets`，批量生成为 `/p/:dramaId/batch`。现在四视图的路由有的只带剧集 id、有的只带项目 id，外壳要同时知道两者，所以统一。旧路由全部重定向（§6）。

### 4.2 各视图并入的功能

**剧本视图**（线框“剧本视图”）

- 工具条：AI 写剧本（`/generation/story` 或 `scriptgen`）、导入剧本 / 小说（从 FilmCreate 搬对话框）、提取角色 · 场景 · 道具（一键或分别）、按剧本生成分镜。
- “逐行 / 全文”切换。本集还没有镜头时，全文模式可编辑并写 `script_content`。一旦生成过分镜，剧本以内核的行为准，全文模式只读，避免两份事实源（见 D2）。
- 检查器：选中的行、它挂的镜头与状态、出场角色 / 场景 / 道具、重新配音、跳到分镜或工作台。

**分镜视图**（线框“分镜视图”）

- 卡片 / 表格两种显示。多选后可批量生成或删除，取代旧画布的“工作流分组”。
- 工具条：从剧本重新生成分镜、经典分镜 / 通用片段模式、批量推断景别运镜、添加镜头。
- 镜头检查器 `ShotInspector` 汇集 FilmCreate 里的单镜功能：
  - 画面描述、视频提示词、AI 润色、提示词模板；
  - 角色 / 场景 / 道具绑定（按 id）与参考图顺序（即 @图片N）；
  - 首帧 / 尾帧槽位：生成、上传、提示词编辑、历史、超分，以及“用上一镜尾帧”衔接；
  - 景别、运镜、时长；
  - “更多镜头参数”对话框：灯光、景深、视角、布局锚点、氛围、动作、对白、旁白、按配音拆分、对白 / 旁白配音。
- 通用片段模式（全能提示词流、@图片N 编辑器）只在当前视频模型支持多参考图时显示（方舟 Seedance 2.0）。“改为 grok 视频格式”删除。
- 镜头工作台保留为整页（版本、A/B 对比、选区改片），去掉“旧流程生成”按钮。

**时间线视图**（线框“时间线视图”）

- 现有剪辑、旁白配音、音乐混音不变；返回键由外壳的项目切换取代。
- 旧“视频配置”（分辨率、字幕、对白烧录、水印）并入导出对话框。字幕烧录与水印是否进成片渲染见 D5。

**画布视图**（线框“画布视图与资产面板”）

- 保持内核画布；节点检查器增加“应用并重新生成”“版本历史”。
- 新增“显示资产引用”开关：把镜头引用的角色 / 场景 / 道具画成只读的资产节点，便于看出“改了参考图会让哪些镜头过期”。这些节点不写入内核（见 A3）。
- 旧画布的节点位置与工作流分组不迁移。

### 4.3 资产（角色 / 场景 / 道具）

- 左栏“资产”三项打开**资产面板**（画布线框左侧）。四个视图里都能打开，能边看分镜边改角色。
- `ReferenceLibrary` 扩成**资产库**整页：角色 / 场景 / 道具三个标签（现在缺道具）。每项可编辑描述、提示词、视觉锚点、多阶段造型；可生成候选、上传、锁定参考图、自动挑选；可存入或导入全局库。方舟可用时显示 SD2 认证与 SD2 音色。
- 首页的“素材角色 / 场景 / 道具”三个对话框与 `MediaLibrary` 合并成一个“全局素材库”页（角色 / 场景 / 道具 / 图片视频四个标签）。
- 资产出图改走生成队列（任务中心可见、受花费上限约束），不再直调旧 `POST /images`。

为什么不做第五个标签：资产是跨集共享的，而四个标签都是“这一集”的不同投影。把资产放进标签会让“切集保留视图”的语义变混。面板加整页既能就地改，又不打破四视图的对等关系。

### 4.4 生成菜单

| 项 | 实现 |
|---|---|
| 一键成片 | 把 FilmCreate 的一键全流程抽成 `usePipeline`（提取角色、场景、道具，生成分镜，推断参数，首帧，视频，配音，组装时间线）。先显示计划与预估花费再执行；保留暂停 / 继续，去掉阶段间倒计时 |
| 只补齐过期与未生成的 | `gen.ask` + 内核过期列表 |
| 全部首帧 / 视频 / 配音 | 现有 `GenerateDialog` 与配音接口 |
| 导演模式 | 现有 `DirectorPanel` |
| 多集批量生成 | 现有 `BatchPage`，放进外壳 |

### 4.5 导出菜单（每个项目页都有，Ctrl+E）

| 分组 | 项 | 来源 |
|---|---|---|
| 成片 | 导出成片 MP4（分辨率、帧率、编码器、AIGC 标识；需要渲染核心） | `ExportPage` 改成对话框 |
| 成片 | 快速拼接（不需要渲染核心，不带字幕与混音） | 旧 `finalize` / `videoMergeService`；开源版没有渲染核心时的退路，见 D4 |
| 工程 | 剪映草稿；Premiere XML / FCPXML | `ExportPage` |
| 工程 | 字幕 SRT | FilmCreate 的“导出解说 SRT”搬成独立工具函数 |
| 素材与项目 | 分镜表 Excel | FilmCreate 的“导出分镜表 excel” |
| 素材与项目 | 项目包 ZIP（可再导入） | FilmList 的“导出项目” |
| 素材与项目 | 素材包（按镜头整理首帧、视频、配音） | 新增；放在 P4 末尾，可单独延后 |

渲染核心不可用时，“导出成片 MP4”置灰并说明原因，其他项照常可用。

### 4.6 首页（线框“首页与新建项目”）

- “新建项目”四个入口：一句话写剧本（现 `NewProject` / `scriptgen`）、导入剧本或小说、空白项目、导入项目包。前三个完成后进入剧本视图。
- 项目卡片点进“上次停留的集和视图”，没有记录时进第 1 集剧本。更多菜单里有导出项目包、改名、删除。
- 示例项目、AI 配置、模板、任务、花费、云备份入口保留。

## 5. 数据与后端

### 5.1 原则

- 镜头、剧本行、时间线的写入只走内核意图或已改道的兼容接口（kernel-design §12）。本方案不新增直接写这些表的地方。
- 资产相关写入继续走旧接口（A3）。
- 所有花钱的生成都走生成队列或带估价确认的接口。新页面不再调用受 `legacySpendGuard` 保护的旧直接扣费接口。
- 新增一个只读接口 `GET /episodes/:id` 返回 `drama_id`，供旧剧集路由重定向使用。

### 5.2 需要你拍板的决定

| 编号 | 问题 | 建议 |
|---|---|---|
| D1 | 资产放第五个标签，还是面板 + 整页？ | 面板 + 整页（§4.3） |
| D2 | 生成分镜后，剧本还能不能整篇改？ | 不能；改用逐行编辑，全文只读，避免两份剧本 |
| D3 | “从剧本重新生成分镜”会清空撤销历史，怎么处理？ | 改成一次内核事务（删旧镜头 + 加新镜头），可整体撤销。做到之前先弹确认，说明“会清空撤销历史” |
| D4 | 开源版没有渲染核心，要不要保留旧的快速拼接？ | 保留，标明“不带字幕与混音” |
| D5 | 旧“视频配置”里的字幕烧录、对白烧录、水印放到哪？ | 进成片导出选项，需要渲染核心支持，另立任务；快速拼接不支持 |
| D6 | 旧画布的工作流分组要不要保留？ | 不保留；用分镜视图多选 + 生成菜单代替 |
| D7 | 通用片段（全能）模式保留吗？ | 只在方舟 Seedance 2.0 可用时显示；Grok 格式转换删除 |
| D8 | 旧路由重定向保留多久？ | 一个版本，之后删除 |

这些决定会记到 `docs/phase3-plan.md` 的“待决定”里，由你确认后再实施。

## 6. 路由与迁移

| 旧地址 | 重定向到 |
|---|---|
| `/drama/:id` | `/p/:id`，再进上次停留的集和视图 |

“上次停留”按项目存在本机 `localStorage`。读不到时用默认值（第 1 集剧本）。

## 7. 测试

- 每个迁入的功能带单元测试。renderer 现有的 `node --test` 纯函数测试模式适用于：外壳状态、路由重定向表、导出菜单可用性判断、流水线步骤编排。
- 后端改动带 `packages/local/test` 测试，并跑内核一致性报告，要求 0 失败。涉及的后端改动有：D3 事务化重新生成分镜、`GET /episodes/:id`、§2 列出的 3 个接口问题。
- e2e：更新现有脚本，新增一条冒烟流程：首页、新建、剧本、生成分镜（假服务商）、时间线、导出菜单。
- 删除旧页面的 PR 里加一个检查：渲染端源码中不再出现指向 `/film/`、`/drama/` 的跳转。
- 真实服务商的出图、出视频、配音需要你在本机用真实 key 验收。Claude 只能用假服务商测。

### 10.2 草稿 / 成片质量档

- 目的：用户可以先用低成本、低精度反复尝试和修改，最后一次性用成片质量重跑所有内容。
- 项目级设置 `quality`：`draft` 或 `final`，顶栏有切换。草稿档选每个服务商里最便宜、最快的模型和最低分辨率（档位表放在一个数据文件里，可调）。
- 每个新产物的版本元数据记录它是用哪一档生成的。切换质量档本身**不**让现有产物过期（只标记，不动），但“生成”菜单多一项“按成片质量重跑草稿产物”，只重跑那些采用版本为草稿档的节点，生成前显示数量与预估花费。
- 导出成片时如果还有草稿档产物，导出对话框给出提示（不阻止）。

### 10.3 整个项目备份

- 现有项目包 ZIP 只含旧表数据与媒体，**不含**内核的版本历史与撤销记录。新的“完整备份”把每个剧集的内核快照（图、版本、操作历史）一起打进包里，恢复时还原。
- 入口：导出菜单“完整项目备份…”，首页项目卡片菜单“备份 / 从备份恢复”，另有云备份（已有）。
- 破坏性操作（重新生成分镜、按成片质量重跑全部）执行前自动在本机保存一份快照，保留最近 5 份，可在“历史”抽屉里恢复。
- 恢复总是还原为**新项目**，不覆盖现有项目。
