# 测试矩阵与真机验证清单（I01）

本文档说明：现在哪些已自动化、哪些只能在真机验证、测试者该怎么测、发现问题怎么报。进度与已知缺口以 `docs/phase1-status.md` 为准。

## 1. 自动化现状

| 范围 | 怎么跑 | 覆盖 | 不覆盖 |
|---|---|---|---|
| local（Node）单测 | `pnpm test`，CI 在 windows-latest 上跑 | 服务商适配器契约（模拟数据）、任务队列状态机与崩溃点、花费上限、时间线、字幕、密钥存储与日志脱敏、错误码表一致性 | 真实服务商返回、真实 safeStorage |
| renderer 单测 | 同上 | 任务中心视图逻辑、快捷键、时间线数学、错误 toast 文案 | 浏览器里的真实交互、拖拽手感 |
| desktop 单测 | 同上 | 托盘 / 退出确认 / 通知合并 / 唤醒对账（假 Electron 对象）、自动更新控制器与配置判定 | 真实 Electron 进程、真实托盘与通知、真实更新 |
| core（Rust）单测与客户端测试 | `core.yml`，windows-latest | JSON-RPC、media.probe、encoder.detect 解析、渲染计划与场景缓存、真 ffmpeg 渲染（软件编码） | 硬件编码器真实可用性、不同驱动 |
| cloud 单测 | `packages/cloud/test`（内存仓库） | 邀请、登录、刷新轮换、设备、ES256 许可证 | 真实 Postgres 迁移、部署 |
| 构建 | CI：`pnpm build`、`pnpm dist:win` | 前端能构建、NSIS 安装包能产出 | 安装包能否在真机装上、启动、被杀软放行 |
| 密钥扫描 | `pnpm secrets:scan`（CI 已接） | 仓库内疑似密钥 / JWT / 签名链接 | 不替代人工审查 |
| 许可证扫描 | `pnpm licenses:check` | 依赖许可证 | 二进制（FFmpeg 等）的合规需人工 |
| 真 Key 连通检查 | `bailian-live.yml`（手动触发，需 Secrets） | 百炼文本 / 图像 / 配音 / 视频 | 方舟与火山语音尚无对应工作流 |

目前没有任何自动化 UI 端到端测试（Electron 或浏览器）。

## 2. 必须真机验证的项目

| 项目 | 为什么 CI 测不了 |
|---|---|
| 安装 / 卸载 / 覆盖升级、开始菜单与桌面快捷方式 | 需要真实 Windows 会话与权限弹窗 |
| 系统密钥加密（safeStorage / DPAPI）保存 API Key，重启后仍可用 | CI 无 Electron 运行环境 |
| 托盘图标、关闭按钮隐藏到托盘、退出确认、完成通知 | 需要真实桌面 |
| 睡眠 / 休眠唤醒后任务对账 | 需要真实电源事件 |
| 硬件编码（NVENC / QSV / AMF）检测与导出 | 需要对应显卡与驱动 |
| 长视频导出的性能、取消、磁盘空间不足、中文路径、含空格路径、OneDrive 重定向目录 | 环境相关 |
| lycore 命名管道、杀软对 lycore / FFmpeg 的拦截 | 需要真实杀软 |
| SmartScreen 提示、签名发布者显示 | 需要签名后的包与真实信誉状态 |
| 自动更新全流程（发现、下载、确认、重启安装、任务恢复） | 需要更新源与签名包 |
| 方舟 / 火山 / 百炼真实 Key 下的各能力（默认模型名、报文、鉴权头、错误码字符串） | 需要真 Key 与费用 |
| 高 DPI / 多显示器 / 缩放 125%–200% 下的界面与时间线 | 视觉问题 |

## 3. 测试矩阵

纵向是环境，横向是功能。每格填：通过 / 失败（附缺陷编号）/ 未测。建议先覆盖加粗行。

说明：

- H 列预期结果：能检测到的编码器被推荐并导出成功；检测失败时自动回退软件编码且给出可读提示，而不是卡死。
- K 列每个环境至少换两款杀软（Defender + 360 / 火绒 / 电脑管家之一）。
- 系统版本再区分：Win 10 22H2、Win 11 23H2 及以上；中文系统与英文系统各一台；标准用户与管理员账户各测一次安装。
- 记录每台机器的信息：Windows 版本号（`winver`）、显卡与驱动版本、杀软及版本、内存、系统盘剩余空间。

## 4. 测试者手册

### 准备

1. 从 CI 产物下载安装包，用 `Get-FileHash -Algorithm SHA256 <文件>` 对比发布说明里的哈希。
2. 若是未签名测试包，SmartScreen 会提示：点“更多信息”→“仍要运行”。已签名包应显示发布者名称，如不一致请报缺陷。
3. 准备自己的服务商 Key（百炼 / 方舟），注意视频生成会产生费用，测试前把单次与月度费用上限调小（费用界面 E05 尚未做，目前通过本地配置调整，向开发确认方法）。

### 手动检查清单（每台机器按序做）

- [ ] A1 安装到默认目录成功；A2 首次启动在 10 秒内出现主界面；A3 重启后数据仍在。
- [ ] A4 卸载干净（程序目录移除；用户数据是否保留符合预期）。
- [ ] B1 填入 Key 保存成功，界面只显示末 4 位；B2 重启应用后 Key 仍可用；B3 “连通测试”通过；B4 填错 Key 时提示可读，并带建议操作。
- [ ] C1 新建项目并生成分镜表；C2 模型返回异常时有中文提示，不白屏。
- [ ] D1 提交一张图片任务，在任务中心看到状态变化并成功；D2 提交一个配音任务；D3（可选，有费用）提交一个视频任务；D4 断网后提交，应出现“网络请求失败”类提示，恢复后可重试；D5 取消一个排队中的任务。
- [ ] E1 任务完成时弹出系统通知，点击能回到窗口；E2 点窗口关闭按钮后程序仍在托盘；E3 托盘“退出”在有任务时有确认。
- [ ] F1 时间线拖拽、吸附、切分、撤销 / 重做；F2 关闭后重开能恢复草稿；F3 缺素材的片段有明确标记。
- [ ] G1 导出 1080p 短片（约 30 秒，含旁白、音乐、字幕）成功，音画同步，成片能被系统播放器打开；G2 导出过程中取消，临时文件被清理；G3 中文路径与含空格路径；G4 只改一镜再导出，耗时明显更短（场景缓存）。
- [ ] H1 在设置 / 导出页看到检测到的编码器与推荐项；H2 选硬件编码导出成功；H3 拔掉外接显示器或切换省电模式后再导出，要么成功要么清晰回退。
- [ ] I1 有任务在跑时让电脑睡眠 5 分钟以上再唤醒，任务能继续或正确失败，不重复提交（核对服务商控制台没有重复任务）。
- [ ] J1 配置测试更新源后，启动 15 秒后自动检查；J2 托盘“检查更新”；J3 下载完成后弹窗，选“稍后”不会重启；J4 选“立即重启并安装”后升级成功、任务恢复、版本号变化。
- [ ] K1 安装、首次运行、导出过程中杀软无拦截；若有拦截，按 `docs/release-signing.md` 第 5 节保存证据并报缺陷。

### 导出日志

日志位置：`%APPDATA%\talekiln\main.log` 与 `%APPDATA%\talekiln\local\logs\app.log`。日志已做密钥脱敏，但提交前请自己快速浏览一遍，确认没有个人信息。**任何情况下都不要把 API Key 贴进缺陷报告或聊天。**
